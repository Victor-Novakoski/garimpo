# Garimpo

Acha as vagas brasileiras de tecnologia que combinam com um perfil e entrega as melhores com nota e motivo. Projeto de portfólio do Victor (Go + React) e a ferramenta que ele usa para procurar o segundo emprego. Roda só na máquina dele.

## Stack

Go 1.25 (coleta, nota, CLI e API; roteador `net/http`, driver `pgx`, `yaml.v3`, SDK oficial da Anthropic) · PostgreSQL no Supabase, SQL puro com migrações embutidas, sem ORM · painel em React + Vite + TypeScript, sem biblioteca de rotas, estado ou componentes, embutido no binário · GitHub Actions só para a CI.

## Comandos

```bash
go test -race ./... && go vet ./... && gofmt -l .   # o gofmt tem que sair vazio
go run ./cmd/garimpo collect -why            # coleta, filtra e dá nota (precisa do profile.yaml)
go run ./cmd/garimpo collect -ai local -why  # soma a nota da IA pelo claude -p
go run ./cmd/garimpo serve                   # API + painel em http://127.0.0.1:8080
go run ./cmd/garimpo migrate                 # aplica as migrações no banco de GARIMPO_DATABASE_URL
go run ./cmd/garimpo-api                     # a API avulsa, com o token em GARIMPO_API_TOKEN

npm --prefix web ci                          # Node 22.22+ ou 24.15+ (o web/.npmrc recusa versão antiga)
npm --prefix web run lint && npm --prefix web test && npm --prefix web run build
```

Os testes do banco só rodam com `GARIMPO_TEST_DATABASE_URL` apontando para um Postgres descartável (o mesmo que a CI sobe em `.github/workflows/ci.yml`); sem ela, são pulados. As variáveis estão no `.env.example`.

## Como se orientar

- Leia `docs/INDEX.md` e abra só o que a tarefa pede. Cada pasta de `internal/` com regra própria tem um `CLAUDE.md`.
- Estados da vaga e o que cada tela faz: `docs/FLOW.md`. Vale igual para a CLI, a API e o painel.
- Fonte nova de vagas passa antes por `docs/SOURCES.md`.
- Tarefas abertas são issues do GitHub (etiquetas `prioridade` e `ideia`).

## Regras gerais (não quebrar)

- **Nunca se candidata sozinho.** O Garimpo acha, filtra, dá nota e prepara; o clique final é de uma pessoa.
- **Sem LinkedIn** e sem site que proíba coleta automatizada. Gupy só como uso pessoal (ver decisão 008).
- **A IA não manda na regra.** O filtro duro roda antes; a IA só escolhe uma classe e o código dá os pontos (ver `internal/ai/CLAUDE.md`).
- **Nota explicável:** todo ponto da nota tem um motivo legível.
- **Dados pessoais fora do repositório.** `profile.yaml` e currículo reais nunca são commitados; só o `profile.example.yaml`.
- **Segredo só no ambiente.** URL do banco, tokens e chaves vêm de variável: nunca em flag, arquivo do repositório, log ou mensagem de erro. **Nenhuma senha em docs**, nem de teste: diga onde ela é definida.
- **Testes sem rede.** Coletores e IA usam respostas salvas em `testdata/`; banco só num Postgres local ou o da CI, nunca o do Supabase.
- **O painel não sai da máquina.** Sem deploy, login ou CORS aberto (ver `docs/SECURITY.md`).
- Sem serviço pago além da IA; banco no plano grátis.
- Textos para pessoas (docs, CLI, painel) em português do Brasil; código, arquivos e identificadores em inglês.

## Git e PR

- Trabalhar a partir da `develop`; todo PR vai para a `develop`, nunca para a `main`.
- Commits com a identidade do Victor (`Victor-Novakoski`), sem trailer `Co-Authored-By` de IA, sem link de sessão, sem assinatura de IA.
- Um commit por tarefa, com `gofmt`, `go vet` e testes passando entre eles. Mexeu no `web/`: lint, testes e build dele também.
- A integração do GitHub põe sozinha um rodapé "Generated by Claude Code" na descrição do PR. Remover.
- A CI roda em PR e em push para `develop` e `main`.

## Manutenção dos docs

- Antes de uma tarefa, leia docs/INDEX.md e abra só o que ela pede.
- Ao terminar, se aprendeu algo não documentado que faria falta, registre no CLAUDE.md do módulo.
- Doc passou de ~150 linhas? Divida por subtema e atualize o INDEX.
- Decisão de arquitetura nova → arquivo novo em docs/decisoes/.
- Se o código contradiz o doc, o código vale: corrija o doc e avise.
